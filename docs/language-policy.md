# Language policy — Rust where it lives, Python where it visits

Adopted 1 Aug 2026, completed 4 Aug 2026 (v1.4.0). This is the rule
every new feature follows, and the reasoning, so the next contributor
(or the next Claude session) does not have to re-derive it.

## The rule

| If the process… | Write it in | Why |
|---|---|---|
| **stays resident** (spawned at login, runs until logout) | **Rust** | it pays its memory bill every second of every day |
| **opens on demand, does a job, exits** | Python (Textual/GTK) or bash | zero resident cost; Python's UI velocity wins |
| is glue between programs | bash | it already is |

Measured basis, 4 Aug 2026 — the whole resident fleet after the
migration: **4.65 % CPU / 64 MB**, against ~9 % / ~350 MB for the same
fleet in Python. A resident Python process costs ~50 MB before it does
anything (interpreter + GTK/Textual); a resident Rust one costs 2–16 MB
doing the same job. For a process that runs for five seconds, none of
that matters — which is why Settings (2,016 lines of Textual, including
Wi-Fi dialogs) stays Python and always will.

## Who is what (v1.4.0)

**Rust residents** (`rust/`, one bin crate each, shared `hyprdesk` crate):
`hypr-cardhost` · `hypr-appdock` · `hypr-office2d` · `hypr-pet` ·
`hypr-viz` · `draveniq` · `hypr-docker` · `serial-watch`

**Python on demand** (`bin/`, shared `lib/hyprdesk`):
`hypr-settings` · `hypr-launcher` · `hypr-kanban` · `hypr-arrange` ·
`hypr-widgetpicker` · `hypr-appdock-picker`

The Python twins of migrated tools stay in `bin/` on purpose: they are
the executable spec each port was parity-tested against, and a machine
without cargo still gets a working desktop from them (`install.sh`
installs Python first, then lets the binaries win).

## The contracts (what makes two languages one desktop)

**The files are the interface.** Both `rust/hyprdesk` and
`lib/hyprdesk` parse the same bytes; drift is a visible symptom, not a
silent fork:

- `widgets.conf` — flat `key=value`, **no spaces around `=`** (shell
  readers `grep "^key="`; a spaced write from Rust was invisible to
  them — found live, fixed in v1.3.0). Writes: flock + tmp + rename,
  undo file kept.
- palette roles from `colors.lua` — accent2 titles, accent = "you are
  here" and nothing else, `sub` at rest, good/bad/warn are status-only.
  Pins: good `#8EC07C`, bad `#E06C75`, warn `#E0B25C`.
- layer namespaces (`hypr-card-*`, `hypr-appdock*`, `hypr-dockedge-*`,
  `hypr-viz`) — hyprland layerrules and hypr-arrange match on them.
- ctl sockets (`$XDG_RUNTIME_DIR/*.sock`) — verbs answer `ok`/`err`,
  and a starting instance **probes and exits** if the endpoint is owned.
- signals — `USR1` reposition, `USR2` retheme, fleet-wide.

**Process guards match both cmdline forms.** Every pgrep/pkill in
`desktop-widgets.sh`, `wallpaper.sh` and Settings tries
`python3 <path>` *and* `<path>`, always with `-xf`, never `-f`.

## Porting discipline (if something else ever migrates)

1. The Python file is the spec — read all of it first.
2. Build the **parity harness before the feature**: run both
   implementations on real data and diff (grid: 1,584 cases; cardspec:
   14 templates byte-identical; live geometry: `hyprctl layers` diff;
   TUIs: scratch tmux server + `capture-pane`).
3. Swap = install binary + both-forms guards + recolor pipeline, in the
   **same commit**.
4. Traps already paid for (details in `rust-migration.md`): fontdue on
   Nerd Fonts (49 MB — use ab_glyph), unbounded transcript reads (48 MB
   file exists — byte-cap), frame callbacks vs calloop timers (92 % CPU),
   banker's rounding (`pyround`), the mix() argument order, measure the
   font-height factor (never guess), and **a stretch-anchored layer
   surface must adopt the configure-granted size before its first draw —
   a Wayland surface IS its buffer** (the 1 px strip).

## Backlog — full Python removal (parked 4 Aug 2026, not scheduled)

Decided and deliberately deferred. If ever picked up, the order is:

1. Delete the superseded `bin/` twins of migrated tools — cheap, but it
   removes the no-cargo fallback, so the repo becomes Rust-required.
2. Port the on-demand TUIs one at a time, easiest first, riskiest last:
   `hypr-widgetpicker` → `hypr-launcher` → `hypr-kanban` →
   `hypr-arrange` → `hypr-settings` (~5,700 lines total; the Settings
   Wi-Fi dialogs are the regression risk that keeps it last).

Until then: every **new** feature is born in Rust (hypr-docker was);
the Python apps receive maintenance fixes only.

## Exception: `hypr-voice` (29 Aug 2026)

The voice daemon is a Python 3.12 pilot (rung 1, like Hypr Settings): openWakeWord's trained ONNX pipeline has no Rust ecosystem. Measured cost and the Rust lever are in `perf/voice-baseline.md`; it ports to `ort` when that cost matters.
